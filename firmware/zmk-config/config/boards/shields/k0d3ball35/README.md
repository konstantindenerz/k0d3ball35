# k0d3ball35 ZMK shield

Shield definition for the k0d3ball35 split keyboard: 35 keys on two separate PCBs
(left 15 finger + 3 thumb keys, right 15 finger + 2 thumb keys). The right half is
the split central and carries the PMW3610 sensor for the 19.05 mm trackball.
Geometry comes from `hardware/layout/output/points-*.json`, the pin map from
`docs/01-design-spec.md`; the physical layout files are generated by
`firmware/zmk-config/scripts/gen_physical_layout.py`.

Files

| File | Purpose |
|------|---------|
| `k0d3ball35.dtsi` | matrix transform, kscan with the shared row/column pins, input-split scaffold |
| `k0d3ball35-layouts.dtsi` | physical layout (ZMK Studio, keymap editors) |
| `k0d3ball35_left.overlay` | left half; left-ball sensor block (commented) |
| `k0d3ball35_right.overlay` | column offset, SPI, PMW3610, input listener |
| `Kconfig.defconfig` | central role, pointing, SPI defaults |
| `k0d3ball35.zmk.yml` | metadata for ZMK tooling |

See `docs/05-firmware.md` for building, flashing and tuning.

Both halves use the identical controller pin set, so the kscan GPIOs are defined once in
the shared dtsi. The left PCB routes the four sensor lines to test pads, which is why a
left-ball build (see the commented block in the left overlay) uses the same pins.

| Line | Both halves |
|------|-------------|
| COL0..COL4 (pinky..inner) | D4 D5 D6 D7 D8 |
| ROW0..ROW3 (top..thumbs) | D21 D20 D19 D18 |
| TB_SCLK / SDIO / NCS / MOT | D15 / D16 / D10 / D14 |

Matrix transform: 4 rows x 10 columns (right half with `col-offset = <5>`). Row 3 holds
the thumb keys, `RC(3,2) RC(3,3) RC(3,4)` on the left and `RC(3,8) RC(3,7)` on the right
(right middle thumb next to the centre, right outer thumb next to the ball).
