# Check the gerber zip in a gerber viewer before ordering

## Context

The fabrication files are generated by `scripts/export.sh` and only verified by KiCad's own DRC. A second pair of eyes in an independent viewer (JLCPCB upload preview, gerbv, tracespace) catches wrong layer assignment, missing drill files or an open outline.

## Acceptance criteria

- [x] Independent parse of `hardware/left-pcb/k0d3ball35-left-gerbers.zip` and `hardware/right-pcb/k0d3ball35-right-gerbers.zip` (gerbonara, `tests/test_gerbers.py`): 2 copper layers, extents 121.0 x 86.7 mm per half (the right grew to the left's size in r2.3), outlines closed, one outline polygon each (no internal cutout), the octagonal notch (apothem 15 mm, centre at KiCad 107/-126 since r2.3) only on the right board with no copper inside it
- [ ] Upload both zips to the JLCPCB preview and confirm the same there: 2 layers detected, dimensions about 121 x 87 mm per half, no DFM complaint about the notch
- [x] PTH and NPTH drill files both present with gerber X2 maps; hit counts per tool match the pads and vias of the `.kicad_pcb` files exactly
- [x] Drill counts per tool match spec/06-fabrication.md (the checklist there now states three 3.05 mm and three 0.40 mm holes per key, 54 / 51; fixed 2026-11-06)
- [x] Silkscreen readable, `RIGHT half` on the right board's F.SilkS, `LEFT half` on the left board's F.SilkS (r2 has two separate PCBs, so there is no text on the other side any more), zero silkscreen pixels over mask openings on all six sides
- [x] Battery bay: dashed 21 x 41 mm rectangle plus the texts `LP552035 cell`, `350 mAh`, `leads +y` on B.SilkS under the controller, mirrored and readable from the bottom on both main boards
- [x] Same checks for `hardware/sensor-pcb/fab/k0d3ball35-sensor-r1-gerbers.zip`
- [x] Zips contain exactly the 14 expected fab files, nothing else; main boards use `.gbr`/`.drl` naming

## Notes

Automated checks live in `tests/test_gerbers.py` (needs `gerbonara`, `cairosvg`, `pillow` in the venv,
listed under the `test` extra; the module skips when they are missing). The test run also renders
the layer stacks for a visual pass:

- `build/gerber-check/left-top.png`, `build/gerber-check/left-bottom.png`
- `build/gerber-check/right-top.png`, `build/gerber-check/right-bottom.png`
- `build/gerber-check/sensor-top.png`, `build/gerber-check/sensor-bottom.png`

The bottom views are mirrored (seen from below), so the battery bay text reads normally there.

Findings (2026-11-06, exports of 10:15 for the main boards, 07:39 for the sensor board):

- Drill tables from the zips, identical to the pad and via counts of the boards:
  left NPTH 3.40 x 18, 1.70 x 36, 3.05 x 54, 2.20 x 5, 0.85 x 2; PTH 1.00 x 26, 0.40 x 54, 0.30 x 99.
  Right NPTH 3.40 x 17, 1.70 x 34, 3.05 x 51, 2.20 x 5, 0.85 x 2; PTH 1.00 x 26, 0.40 x 51, 0.30 x 100
  (102 before the two stitching vias of `hw-main-pcb-review-r1` were dropped on 2026-11-07;
  re-exported the same day, so use the current zip).
  Sensor PTH 0.80 x 16, 0.30 x 23; NPTH 2.20 x 2.
- spec/06-fabrication.md states two 3.05 mm socket boss holes per key (36 / 34). The reversible
  Choc footprint `SW_Choc_V1_HS_reversible` has three, so the boards and gerbers have 54 / 51.
  The 0.40 mm diode joiner holes are also three per key (54 / 51). Update the checklist in spec/06.
- Board extents in the gerbers (outline stroke subtracted): left 120.98 x 86.70 mm, right 120.98 x
  86.70 mm (both halves are the same size since r2.3), sensor 26.00 x 25.00 mm.
- Right notch in Edge.Cuts: one 45 degree side of 12.43 mm between a horizontal side at y = 109 and
  a vertical side at x = 110 (KiCad coordinates), i.e. a regular octagon with 15 mm apothem around
  the pocket centre (107, -126) = layout (-13, 66). No board material or copper inside the octagon.
- No copper outside the outline on any board (0.0 mm2; the sensor board shows 0.04 mm2 of raster
  slop at its rounded corners, below the tolerance).
- Cosmetic: the test pad labels on F.SilkS (`TP1`..`TP9` left, `TP1`..`TP5` right) sit 2.2 mm right
  of their 2.5 mm pitched pads in 0.8 mm font, so each label runs into the next pad's mask opening
  and is clipped by the export's mask subtraction; the board reads `T T T T TP9`. Harmless for the
  fab, fix in the generator by moving the reference below the pad or hiding it.
- Sensor zip: the outline has a second closed polygon, the 16.96 x 8.6 mm sensor window at
  x 2.0..18.96, y 8.2..16.8 (intentional, not an open outline). B.Paste is empty (no bottom SMD
  parts). `hardware/sensor-pcb/export.sh` passes `--no-protel-ext`, so the zip uses the same
  `.gbr` / `.drl` naming as the main boards (14 files, checked by `tests/test_gerbers.py` with
  `protel: False`; an earlier note here claimed protel extensions, which was wrong). spec/03 and
  spec/06 point to the zip to upload, `hardware/sensor-pcb/fab/k0d3ball35-sensor-r1-gerbers.zip`.
